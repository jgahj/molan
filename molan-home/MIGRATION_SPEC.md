# 墨阑统一工作台功能补齐规格

## 目标

在不改变 `index.html` 现有视觉系统、布局结构和后端接口的前提下，把原项目页面中已经存在的功能迁移到统一工作台。所有列表、编辑、任务、导入和 AI 操作必须使用当前登录账户与当前作品的真实数据，不使用原型占位数据作为最终状态。

## 功能范围

1. 首页与我的小说：真实账户作品合并、筛选、排序、分组、搜索、创建、打开、重命名、删除、刷新、待同步和当前编辑定位。
2. 编辑器：章节/卷/场景管理，正文加载保存，正文格式工具，导入导出，搜索替换，回收站，版本历史与差异，设定集/伏笔/大纲落点，布局状态。
3. AI 工作流：统一模型，真实上下文召回，Skill 注入，流式对话，续写/生成下一章/润色/扩写/改写/查错/大纲/角色/设定/灵感/一致性/风格仿写，任务进度、取消、重试、结果接受/撤销和积分展示。
4. 资源中心与拆书：多文件/文件夹、粘贴、格式识别、正文切分、设定抽取、阶段进度、积分预估/实际消耗、失败重试/恢复、完整结果 Tabs、导出和带入编辑器。
5. 知识库与 Skill：分类树、搜索、实体详情、批量操作、关系和引用信息；Skill 私有保存、上传、查看、编辑、发布、撤回、重新发布、下载和同步。
6. 账户、工具、教程、积分和登录：头像与全局登录态、账户 Tabs、完整工具卡与流式结果、教程筛选详情、使用记录、普通/管理员登录辅助流程。
7. 管理后台：用户、模型倍率、全局 Skill、数据中心、审计日志的真实查看、筛选、分页、编辑、保存、撤销、删除和退出。

## 约束

- 不新增独立视觉系统，不替换现有 CSS 设计语言。
- 不修改物理数据模型和服务端 API 契约；若已有 API 不足，前端保持兼容并提供明确的空态/不可用态，不伪造成功。
- 所有用户可见示例内容在真实数据加载后必须被替换；未登录或无作品时显示真实空态。
- AI 结果必须先进入对话/结果区，只有用户确认后才写入正文、设定、大纲或伏笔。
- 所有耗时操作必须显示状态；失败必须可重试，支持的任务必须可取消。

## 本轮导入补齐规格

- 所有内容导入入口都必须同时支持单个文件、多选文件和整个文件夹。
- 文件夹选择使用浏览器原生目录选择能力，读取 `webkitRelativePath` 作为相对路径；单文件和多文件选择继续保留。
- 同一个导入批次按相对路径、文件大小和修改时间去重，文件夹中的不支持格式应跳过并明确提示，不得静默写入。
- Skill 导入以文件夹内的 `SKILL.md` 为入口，同时保留文本附属文件的相对路径；现有保存接口的数据格式不变，无法保存二进制附属文件时应明确提示。
- 文库 JSON 导入支持多个 JSON 文件和文件夹中的 JSON 文件，并沿用现有合并逻辑；无效 JSON 或不符合文库格式的文件逐个报错，不影响其他文件继续处理。
- 编辑器正文导入、知识库导入和 Skill 编辑器也必须提供单文件/多文件与文件夹两个入口；重复选择只追加新文件，按相对路径、大小和修改时间去重，用户可以显式清空当前清单。
- 私有 Skill 列表的名称允许截断，但状态和操作按钮必须固定在可见区域内，不得换行、遮挡或被窄侧栏裁切。
- 头像上传是单张图片资源，不属于内容导入，不增加文件夹选择入口。

## 验收标准

- 登录后首页、小说库、编辑器、资源、Skill、账户和后台均按真实账户数据渲染。
- 点击任意作品可以进入对应作品和对应章节，编辑保存后重新打开内容不丢失。
- AI 流式内容在生成过程中逐块显示；停止后不继续占用前端任务状态。
- 导入、抽取、拆书、检测和工具任务均展示进度、积分预估/实际结果和失败状态。
- 所有原项目已有入口在统一工作台中有对应可操作入口，不能只弹 Toast 或静态展示。
- `node --check`、现有 `node --test` 和关键页面交互检查通过。

## 本轮控件统一规格

- 首页工作台中的原生 `select`、输入框、按钮和筛选工具统一使用现有黑白细线视觉：同一高度、边框、圆角、字体、内边距和焦点状态。
- 下拉框必须保留原生键盘和表单语义，但隐藏浏览器默认外观并使用统一的向下箭头；打开选项时不得改变布局宽度。
- Skill、小说库、账户、资源、拆书和模型筛选控件复用同一基础样式；专用紧凑控件只允许通过局部修饰调整尺寸，不得重新引入浏览器默认样式。
- 控件在窄屏下允许收缩或换行，不得溢出、遮挡或出现不可滚动的横向布局。
- 动态后台、知识库和编辑器沿用首页公共面板、表单、标签和交互反馈规则；可点击节点必须有 hover 与键盘 focus 状态，不能退化为浏览器默认控件。

## 本轮章节创建规格

- 每个卷的章节列表下方必须提供清晰可见的“新增章节”文字按钮，不能只依赖卷标题旁的图标按钮。
- 新增章节继续复用现有创建弹窗，标题必填；创建后生成一个空白默认场景，并自动选中新章节和默认场景。
- 新章节必须写入当前作品的真实 `state.volumes` 数据，沿用现有脏状态与保存链路，不使用占位数据。
- 没有章节时，编辑器正文空态必须明确引导用户使用“新增章节”入口；已有章节、场景和卷的操作不受影响。
