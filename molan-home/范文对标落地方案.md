## 一、 方案背景与核心宗旨

墨阑系统通过“名家范文对标工程”，旨在打破传统大模型网文生成中普遍存在的**“大纲化假大空”、“通篇人人形色紧绷人人藏机锋”、“无端骨节泛白与躯体过度应激”、“千字堆叠浮夸比喻”、“因果账本前后断层”**等典型 AI 语病。

本方案的核心宗旨是：
1. **范本驱动与确定性度量优先**：从百部真正优秀的网文商业范本提取客观数学指纹与行文结构，将模糊的“文学语感”转化为可量化、可拦截、零额外推理成本的本地确定性指标。
2. **项目中立与设定绝不侵染**：通用纠错库与题材基线只规范“人类自然语言规律与商业节奏”，严禁将范本专有人名、功法、设定作为通用硬套模板侵入用户原创作品。
3. **分级注入与经济性**：彻底摒弃将几十KB原始范本或全文纠错库全量塞入 System Prompt 的粗暴做法，依据题材族（`ancient_cultivation`, `ancient_world`, `urban_modern`, `disaster_exploration`, `romance_fantasy`）进行三级精准裁剪注入（核心硬规 ≈1500字、题材场景规则 500~1000字、定向对照审校），单章节约 2.5 万至 3 万 token。
4. **全生命周期闭环**：从起草前的状态合同，到起草期的预算约束与双稿择优，再到审校期的证据链定位（Quote 强校验）与因果债务（Causal Debt）登记，最后回流至用户手改纠错库（Inbox）。

## 二、 固化 7 维量化质量门槛与标准体系

依据对 6 大商业主流题材（玄幻、都市高武、悬疑脑洞、青春甜宠、历史脑洞、科幻末世）真实范本前 3 章的深度统计与 AI 原始生成基线对比，系统正式固化以下 **7 维质量门槛**：

```
+-----------------------------------------------------------------------------------+
|                           墨阑名家范文 7 维量化门槛体系                           |
+-----------------------------------------------------------------------------------+
| 维度 1: 商业标准篇幅与密度控制  | 单章汉字 2000~3000 字 (偏差 ≤ 15%)，严禁截断与水文   |
| 维度 2: 9 字段风格指纹对齐度    | 句长/段长/对白/TTR/比喻综合偏差 ≤ 1.5σ (距离分 ≥ 75)   |
| 维度 3: 结构节奏与单句段配比    | 单句段占比 30%~65%，直接心理 3%~10%，拟声独立段 ≤ 0.5% |
| 维度 4: 实体与人物密度控制      | 前3章新人物 ≤ 3人，单章新专名 ≤ 5个，人名共字 0 冲突   |
| 维度 5: 零 AI 味与生理应激配比  | 低能级场景 0 躯体应激，高能级真实物理生理扰动，0 口癖   |
| 维度 6: 证据链审稿与状态连续性  | 审稿 Issue 必须包含正文 100% 精确可定位 Quote，因果闭环|
| 维度 7: 题材分层与叙事决策卡    | 宏大 vs 市井场景自适应，方言土白与物质阻力，拒绝人人机锋 |
+-----------------------------------------------------------------------------------+
```

### 1. 维度一：商业标准篇幅与密度控制（Chapter Length & Density）
- **硬性指标**：默认单章汉字数稳定在 **2,000 ~ 3,000 字**（测试基准区间：2,200 ~ 2,800 字）。
- **容差边界**：偏离目标字数超过 ±15% 触发 warning；低于 1,800 字或超过 3,500 字触发 blocker。
- **信息密度**：严禁无效景物大段报菜名、严禁连续三段无人物动作或实质推进的信息空转。

### 2. 维度二：9 字段风格指纹对齐度（Style Fingerprint Distance）
基于 `lib/benchmark-metrics.js` 提取的 9 项客观文本特征，计算相对题材基线均值的归一化偏差：
1. `sentenceLenMean`（平均句长）：玄幻 29.4±4.6，都市 22.0±3.5，悬疑 25.3±4.0，科幻 28.1±4.2；
2. `sentenceLenStd`（句长标准差）：保持 15~30 字长短句交错，严禁全篇均一匀速排比；
3. `paragraphLenMean`（平均段长）：范本均值 21~32 字，严禁 AI 常见的 60~100 字巨型段落；
4. `paragraphLenStd`（段长标准差）：12~25 字；
5. `dialogueRatio`（对白字数占比）：15% ~ 35%（科幻偏低约 14%，都市高武偏高约 21%~30%）；
6. `dialogueTurnMean`（单轮对白长度）：14 ~ 20 字，严禁单人独白超过 60 字宣讲；
7. `commaPeriodRatio`（逗句比）：1.5 ~ 3.5，保障呼吸停顿自然；
8. `ttr`（词汇丰富度 Type-Token Ratio）：0.65 ~ 0.76，杜绝高频词单一轮番复读；
9. `similePerKilo`（千字明喻频次）：≤ 4.0 次/千字（范本普遍在 1.0~2.5 次/千字，严禁千字 8~10 次泛滥）。
- **通过门槛**：`computeStyleDistance(fingerprint, baseline).score >= 75`。

### 3. 维度三：结构节奏与单句段配比（Structural Cadence & Paragraphing）
- **单句短段占比（Single Sentence Paragraph Ratio）**：范本前三章单句段占比在 **30% ~ 67%** 之间。短段是网络小说的常态节奏与视觉呼吸，严禁误将单句段判为缺陷。
- **直接心理描写占比（Direct Psych Ratio）**：**3% ~ 10%**。允许有明确主体声音的简洁心理活动（“他知道不能再等了”），禁止机械改造成满头虚汗、牙关咬碎等躯体病态。
- **拟声独立段占比（Onomatopoeia Ratio）**：≤ 0.5%（仅在关键物理撞击或突发警报时使用单字声词）。
- **开篇模式分布（Opening Mode）**：场景动作切入（`scene`，占比约 70%~90%）或对话直接切入（`dialogue`，都市约 30%~50%），严禁连续三段无人物出场的假大空世界观设定交代（`exposition` 必须 ≤ 10%）。
- **章末模式分布（Ending Mode）**：范本中 **60% ~ 75%** 章节以事件兑现后的生活化落定（`ease`）或阶段完成（`fulfil`）收尾，只有 15%~25% 抛出新危机（`newProblem`）。严禁每章机械式“就在这时，一道冰冷恐怖的声音突然响起”式虚假悬念。

### 4. 维度四：实体与人物密度控制（Entity & Name Accumulation）
- **具名人物出场节奏**：黄金前三章累计出场且有独立动作的具名人物 **1 ~ 3 个**，单章新出场人物严禁超过 3 个；
- **全章新专名上限**：单章新实体名词（道具、地名、功法）≤ 5 个，严禁设定集报菜名；
- **人名声韵共字隔离**：`nameCharacterOverlap` 严格检测，同一主要场景中的角色姓名严禁共享同字或极近谐音（如“李青”与“李青云”、“陈峰”与“林峰”），避免读者认知混淆；
- **人物即时牵挂（Character Anchor）**：出场核心人物必须具备一项与当前选择直接关联的历史羁绊、代际承诺或物质牵挂，先成为有血有肉的人，再承担剧情工具。

### 5. 维度五：零 AI 味与场景能级/躯体应激配比门禁（Zero-AI Flavor & Somatic Gate）
- **R-01~R-46 规则 100% 覆盖**：严格执行《纠错库》全量规则，高频劣质套路零容忍（眼神一凝、倒吸凉气、瞳孔微缩、嘴角勾起冷笑、深吸一口气、后背冷汗直流等 Blocker 级别违规为 0 次）。
- **场景能级与生理动作配比门禁（Somatic Gate）**：
  - **低能级场景（日常对话、市井交接、点名吃饭、案头翻账、寻常打量等）**：严禁“指骨/指节捏得发白”、“指腹反复摩挲杯沿”、“食指轻叩桌面”、“喉咙发紧/喉头发干/喉头一哽”、“呼吸骤然一窒”、“牙关紧咬后槽牙作响”。正常人拿杯子就拿，说话就说话，回归自然人类动词（“看/打量/瞧/端起/放下”）。
  - **高能级生死关头**：允许出现生理扰动，但必须是**真实物理环境交互的被动反应**（耳膜被气浪震得尖鸣、泥血糊住睫毛被迫抬手擦拭、冰雪湿滑导致下盘踉跄、兵刃反震撕裂虎口），严禁凭空发作神经性痉挛。

### 6. 维度六：证据链审稿与状态连续性（Evidence-based Review & Continuity）
- **审稿 Issue 强校验**：审稿模型提出的每一条缺陷，必须携带正文中**100% 逐字匹配的原始引文（Quote）**。引文未能在正文准确定位者，降级为 warning 并标 `unverified`，杜绝模型主观臆造的审稿幻觉。
- **状态与因果债务（Causal Debt）闭环**：
  - 空间位置、供电、受力、能量、道具必须保持状态连续，严禁凭空瞬移与机械降神；
  - 每一项承诺、债务、伤势（如“欠下三十两纹银”、“断骨内伤需三日调养”）自动登记入因果账本，后续章节未偿付前持续注入约束，杜绝一出场景就遗忘。

### 7. 维度七：题材分层与叙事决策卡（Genre-Scoped Directives & Narrative Decision Cards）
- **题材分层作用域**：
  - 修真/仙侠/奇幻：强调宗族谱系、灵石微观算计、天地神异敬畏、代际牺牲与物质阻力；
  - 都市现代/高武：生活化切入（学校、宿舍、工位、租房），体制法理与规章行话（现场勘验令、治安管理处罚、公差尺寸），允许现代职场行话；
  - 悬疑怪谈：规则自洽推导、民俗禁忌与熟人社会伦理、感官压迫与冷幽默自嘲；
  - 历史军事：粮饷成色、札甲片数、箭矢磨损、制度考据、名士风骨与底层穷酸解构；
  - 科幻末世：重工业机械公差、滤网辐射衰减、柴油机震颤、避难所流民生存细账。
- **去除“人人暗藏机锋”的模板化病态**：允许真诚的好意、笨拙的坦白、市井的调侃与成年人的无奈妥协，禁止将全员写成心机深沉的同一张谈判桌模板脸。

## 三、 系统落地全链路架构 (P0 ~ P5)

```
[ P0: 方案设计与差距基线 ] 
  ├── 固化 7 维门槛标准
  └── 产出 baseline-2026-09-10/gap-table.md (12 本范本对比)
        │
[ P1: 资产沉淀与题材规则蒸馏 ]
  ├── data/genre-baselines/ (6 题材范本统计指纹)
  ├── lib/reviewed-route-assets.js (叙事决策卡库)
  └── data/genre-rules/ (6 题材规则 JSON)
        │
[ P2: 生成管线对齐与四层落地 ]
  ├── 第 1 层: SSOT 编译 (scripts/build-correction-library.mjs -> rules/cases/blacklist/checks.json)
  ├── 第 2 层: 动态分级注入 (correction-policy.js + completion-editor.js buildScopedWritingDirectives)
  ├── 第 3 层: 审校工具化 (pages/editor.js 全章健康指标卡 + R-01~R-46 定位高亮 + 局部精修)
  └── 第 4 层: 用户纠错闭环 (POST /api/correction-library/inbox -> --merge-inbox 回流)
        │
[ P3: 自动化回归评测基准 ]
  └── data/genre-lab/regression-prompts.json (18 条多题材深度测试集)
        │
[ P4: 长篇多章连续生成稳定性 ]
  └── scripts/run-longform-eval.mjs (10 章长篇连贯性、因果账本与实体累积评测)
        │
[ P5: 部署放行与工程护航 ]
  └── scripts/deploy_molan.py (data 白名单放行 genre-baselines, genre-rules, correction-library)
```

### 1. 编译期（SSOT 结构化）
- 数据源：`editor-sources/纠错库.md` 为唯一真实事实来源（SSOT）；
- 编译器：`scripts/build-correction-library.mjs` 解析出规范化规则库、对照表、黑名单词库与后置正则；
- 产出物：`data/correction-library/{rules,cases,blacklist,checks}.json`。

### 2. 规划与起草期（预算制与决策卡）
- `completion-editor.js` 中的 `buildScopedWritingDirectives(genreFamily)` 依据目标题材动态装配 7 条硬指令（开篇模式、能级配比、方言土白、人物牵挂等）；
- 注入 `reviewed-route-assets.js` 沉淀的对应路线 3 条决策卡（应用方法与边界条件）；
- 双稿择优机制放宽至全章，基于确定性指纹距离分与 blocker/high issue 扣分进行综合打分，优胜稿自动胜出。

### 3. 审校与修订期（证据链与局部精修）
- `benchmark-pipeline.js` 的 `evidenceAudit` 执行确定性硬约束（字数、前缀重复段、状态短语复读、新专名数量、人名共字）+ 纠错库正则扫描 + 模型审计；
- 模型审计 Issue 经过 `verifyModelAuditQuotes` 验证正文逐字匹配；
- 触发局部修订（`localRevise`）：只改目标段落，其余段落 100% 逐字保留，杜绝整篇重写导致的人物与状态漂移。

### 4. 交付与回流期（Inbox 与白名单）
- 用户手改正文若发现典型病句，可通过编辑器浮动菜单一键提交至 `/api/correction-library/inbox`；
- 后台通过 `POST /api/correction-library/merge` 调用编译脚本一键完成增量去重回流；
- 部署脚本 `scripts/deploy_molan.py` 白名单放行结构化资产，既保证云端与本地同步，又严格防止用户私密数据外泄。

## 四、 验收与演进机制

1. **零回归保证**：
   - 每次规则与管线变更必须通过 `node --test test/correction-policy.test.js` 与 `structural-originality.test.js`；
   - 18 条回归 Prompt 评测 Blocker 级别缺陷率为 0。
2. **长篇连续性检验**：
   - 10 章连续生成测试中，新实体引入速度、因果账本闭环率、字数标准方差必须均落入绿区。
3. **持续迭代**：
   - 随着用户创作书的真实反馈，定期从 Inbox 提炼新通用规则并归入 SSOT，保持引擎生命力。
