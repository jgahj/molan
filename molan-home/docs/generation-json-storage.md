# 生成任务原生 JSON 仓储

本地设置 `MOLAN_GENERATION_STORE=json` 后，生成任务、阶段、事件和租约写入 `MOLAN_DATA_DIR/generation-json`；没有设置时保持既有后端。PostgreSQL 模式优先，生产环境仍必须配置 PG。这是生成任务域的显式切换，不代表账户、小说、记忆或文风已经完成迁移。

启动先恢复任务再监听；损坏文件、锁冲突或恢复失败会阻止监听。运行目录只允许单进程写入。正常停机等待提交队列并释放锁。跨项目任务 ID 索引与项目任务创建通过同一个 redo 事务提交。

旧后端任务不会自动复制或删除，切换前需保留原数据库及数据备份。关闭切换后新 JSON 任务也不会出现在旧后端；不要在有运行任务时反复切换。没有实施跨后端任务迁移命令。

启动时，过期任务在安全阶段恢复为暂停，Provider 已发起的阶段标记结果未知且不重发。提交阶段只有注入的真实回执内容哈希匹配才恢复为完成；当前服务端没有注入跨后端回执查询，因此提交中断恢复为等待作者确认。章节提交仍由既有仓储负责，尚未与 JSON 任务域共用事务。

验证：`node --test test/generation-json-store.test.js test/json-file-repository.test.js`。此冒烟不验证真实 PG，不执行付费模型调用。
