## 一、结论先行

项目工程素养很高（SSRF 防护、静态路径穿越防护、SQL 全参数化、SSE 清理、纠错库策略注入均验证在位），但本轮发现 **3 个 P0**，其中两个是"功能看起来在跑、实际生产已死"的静默故障，一个是**质量门禁全面失效**——CI 自 2026-10-08 引入某个测试起从未绿过，最近 25 次运行全部失败/超时取消，而团队所有"全绿"结论均来自本地。**最危险的不是这些 bug，而是"验证体系给出虚假信心"这件事本身。**

## 二、P0 级发现（生产必现 / 门禁失效）

### P0-1 CI 质量门禁自 10-08 起从未生效（全红 + 超时）

| 项 | 内容 |
|---|---|
| 根因 | ① `.github/workflows/ci.yml:64` 用递归 glob `test/**/*.test.js`，而 #18-F 归档只改了 `package.json` 的 `test/*`——CI 仍跑 `test/legacy-json-mode/` 下 18 个已删模式测试（实测 glob 匹配 306 文件，其中 18 个在归档目录；顶层 glob 为 288，差值恰为 18）；② `test/adversarial-m1-discover-patterns.test.js:39-40` 硬编码 Windows 路径 `tools/node22_runtime/node.exe`（该目录被 .gitignore，CI checkout 中不存在），Linux 上 spawnSync ENOENT，`proc.status===0` 断言瞬败 |
| 证据 | GitHub Actions 可查最近 25 次运行（#49–#73）**全部 failed/cancelled**：#71 失败于 discover-patterns 系列（40s 秒败，与 ENOENT 特征吻合）；#72/#73 分别 15min 取消、**25min36s 撞 timeout-minutes:25 上限** |
| 影响 | push/PR 零有效门禁；缓存戳门禁、生产导入审计、Golden 审计全部从未在 CI 执行过；失败信号被淹没后团队会习惯性忽略 CI |
| 修复方向 | ci.yml glob 与 package.json 对齐（`test/*.test.*` 或显式排除 `test/legacy-json-mode/**`）；discover-patterns 测试改 `process.execPath` + `existsSync` 回退；CI 超时 25→40min 或测试分片；修复后必须实跑一次确认绿（可能暴露更多环境依赖失败） |

### P0-2 创书 6 端点生产必现 500（PG handler 漏接线）

| 项 | 内容 |
|---|---|
| 根因 | `server.js:5658-5673` 注入 `createCreationBookRoutes` 时漏传 6 个 postgres handler（`postgresBiblePut/postgresPlanExpand/postgresPlanReview/postgresLinkNovel/postgresChapterContract/postgresRegenerateAsset`）；这 6 个符号在 `server.js:4612`/`5004-5005` 解构后**全文再无使用**（已 grep 证实）。路由 `routes/creation-books.js` 的模式是 `if (postgresMode && postgresX) … else if (legacyX) …`，undefined 时 fallthrough 到 legacy handler → `loadCreationBookForAuth`（`services/creation-book-service.js:53`）执行 `getDatabase().prepare()`，而 PG-only 收敛后 `db` 恒为 `null`（`server.js:1514`，initDB 已 no-op）、`dbReady()` 返回 PG 健康态恒 true，守卫全部放行 |
| 运行时复现 | 本机以生产同构参数（`getDatabase: () => null` + `dbReady: () => true`）实测：`loadCreationBookForAuth` 抛 `TypeError: Cannot read properties of null (reading 'prepare')`；`saveCreationBibleVersion` 抛 `TypeError: … (reading 'exec')` |
| 受影响端点 | `PUT /api/creation-books/:id/bible`（保存创作圣经）、`POST …/plan-expand`（**章纲分批补全，创书核心流程**）、`…/plan-review`、`…/link-novel`、`…/chapter-contract`、`…/regenerate-asset`——登录用户 + PG 就绪时 100% 复现 500 |
| 为何没被测试发现 | `test/routes-creation-books.test.js` 的 mock tracker 注入了全部 `postgres*` handler，PG 分发测试全绿；**没有任何测试按生产接线方式装配** |
| 修复方向 | 把 6 个 handler 补进 `server.js:5660` 注入表；新增一条"生产接线形态"路由测试（从 server.js 导出面或装配函数取真实 handlers map 断言 6 键非 undefined） |

### P0-3 `getJob` 无属主过滤（IDOR：越权读/取消他人创书任务）

| 项 | 内容 |
|---|---|
| 根因 | `lib/postgres-repository.js:2048-2063`（getJob）、`:2066-2094`（getJobBudget）：SQL 仅 `WHERE j.legacy_id = $1`，`ensureActor` 只确保 actor 行存在、不做任何属主/workspace 过滤；注释却写"当前用户可见" |
| 设计意图反证 | 项目自带 `scripts/postgres-job-smoke.mjs:32-33` 断言 `getJob(otherUser, jobId)` 必须返回 null——当前实现与自家契约矛盾，属 PG-only 收敛回归 |
| 攻击面 | `services/creation-core-job-http-service.js:9/16`（`GET/DELETE /api/creation-books/core-jobs/:jobId`）：任意登录用户枚举 jobId（`cj_<bookId>`，bookId 源自客户端可控的 creationRequestId）即可读取他人任务 result（bookId/bibleVersion/creditCost/errorCode）、取消他人运行中任务；404 文案"或无权访问"名不副实 |
| 修复方向 | getJob/getJobBudget 增加 `workspace_id/project_id` 属主 JOIN 条件（参照 accessForClient 既有模式）；把 job-smoke 的隔离断言纳入 CI 可跑范围 |

## 三、P1 级发现（功能失效 / 安全暴露）

### P1-1 管理后台整体不可用（懒加载回归，72KB 真实管理台成死代码）

| 项 | 内容 |
|---|---|
| 根因 | `completion-admin.js:1030-1037` 的 `install()`（注册 `renderers.admin/admin-login` + bind）唯一调用点在 `workspace-completion.js:10` 的 DOMContentLoaded 遍历——彼时懒加载脚本未就绪，`window.MolanCompletionAdmin` 为 undefined 被跳过；`app-boot.js:59-68` `loadLazyScript` 的 onload 只登记不 install。且 `LAZY_ROUTE_SCRIPTS`（app-boot.js:54-57）只映射 `['admin']`，**不含 `admin-login`** |
| 现象 | `#admin-login` → 脚本根本不加载 → 永久"管理员入口正在加载"；`#admin`（带 token）→ 脚本下载完但 install 永不执行 → `renderers.admin` 仍是 app-boot 占位 → 永久"管理后台正在加载"（app-boot.js:222-231 两个占位函数） |
| 来源 | 2026-10-14 阶段二十六懒加载重构引入；该阶段"浏览器 15/15 通过"未覆盖 admin 真实渲染（只验证了脚本 200 与懒加载触发） |
| 修复方向 | `loadLazyScript` onload 后对已定义模块补调 `install()`（或懒加载守卫重渲前统一 install 一次）；`LAZY_ROUTE_SCRIPTS` 补 `admin-login`；浏览器回归增加"admin 页面出现真实管理台 DOM"断言 |

### P1-2 ECS:10809 公网可达的开放代理链（安全）

| 项 | 内容 |
|---|---|
| 根因 | `scripts/reverse_tunnel.ps1`（已入 git）建立 `ECS:10809 → 本机 127.0.0.1:7897`；本机跑 `molan-home/scripts/direct_gpt_proxy.js`——**无鉴权、无目标白名**的开放 HTTP/CONNECT 代理（任意 URL 转发 + 任意 CONNECT 隧道，`timeout: 0` 全禁，maxConnections=64）。TARGET_HOST 常量实际未使用，脚本实为通用开放代理 |
| 实测 | 本机 `dev/tcp` 探测 8.138.128.184:10809 **TCP 握手成功**（公网可达）；当前代理后端未运行故完整链路暂断（写数据即断），但隧道脚本一跑即构成公网开放代理；SSH 参数还带 `StrictHostKeyChecking=no + UserKnownHostsFile=/dev/null` |
| 影响 | 互联网任意主机可经 ECS 把开发机当跳板访问任意内/外网目标（含开发机 127.0.0.1 本地服务）；64 槽无限期占用即 DoS |
| 修复方向 | 短期：不跑隧道时确认 ECS 安全组回收 10809；长期：proxy 加 token 鉴权 + 目标白名单（仅 GPT 上游），ssh 恢复 host key 校验，`-R` 绑定改 `127.0.0.1` 明确 loopback |

### P1-3 纠错库 merge 缺管理员鉴权（越权管理操作）

| 项 | 内容 |
|---|---|
| 根因 | `routes/admin-handlers.js:154-156` `handleCorrectionLibraryMerge` 只做 `getAuthUser`（登录）检查，无 `requireAdmin`（同文件 :177/:188 的相邻 handler 都有）；`routes/admin.js` 无路由级 admin 闸；server.js:1281 委派同样只查登录 |

| 修复方向 | 补 `requireAdmin(req, res)`；顺手审计全部 `/api/correction-library/*` 与 `/api/admin/*` 的鉴权矩阵 |

### P1-4 外部正文同步存储型注入（数据层污染 + 一条原始渲染路径）

| 项 | 内容 |
|---|---|
| 根因 | ① `completion-editor.js:8723` `MolanEditorApplyExternalDraft`：含 `<p>` 的文本**原样**写入 `scene.content`，绕过编辑器自身输入路径的 `sanitizeHtml`（:1178 存在且 renderEditorPaper 渲染时会过，但持久化值已污染）；② 持久化进 localStorage/后端后，`app-boot.js:2557+2573` 旧编辑器路径 `paper.innerHTML = previewState.editorBody` **无消毒回灌**（`editorBodyFromNovelState` 原样返回）；③ `app-boot.js:4135-4138` postMessage fallback 分支同样原样 innerHTML；④ message 监听（:4122）**无 origin 校验**，发送端 `pages/story-workbench.js` 用 `'*'` |

| 定级说明 | CSP `script-src 'self'` 阻断脚本执行（<script>/onerror 无效），但 `<a href="javascript:">`、UI 钓鱼、版式注入可用，且污染数据持久化跨刷新；明确违反工程内已建立的 sanitize 约定 |
| 修复方向 | `MolanEditorApplyExternalDraft` 统一走 `sanitizeHtml`；`applyNovelState` 回灌路径加消毒；postMessage 校验 `event.origin === location.origin` |
