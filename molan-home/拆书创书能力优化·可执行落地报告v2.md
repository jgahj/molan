## 三、创书参数（把百分比改为可验证约束）

### 3.1 骨架保留：开关 + 级别（替代 90%/85% 百分比）

| 骨架项 | 保留级别（三选一） | 对应提示词约束（写入简报/框架/正文） | 对应验证规则 |
|---|---|---|---|
| 开篇节奏 | `保留`（默认）/ 微调 / 重写 | 保留"异常→不利→首危机→金手指出现→主动选择→收益→更大问题→章末钩子"结构 | 前 3 章必须含 ≥3 次信息变化、≥1 个明确危机（正文审计检查） |
| 金手指成长逻辑 | `保留`（默认）/ 微调 / 重写 | 保留"进入时机/成长阶段/能力逐步开放/奖励-代价循环" | 新书金手指必须含 ≥1 个**新增限制或代价**（原创偏离矩阵必查） |
| 整体架构 | `保留`（默认）/ 微调 / 重写 | 保留"新手→首突破→第一地图→中期势力→世界扩大→真相→高阶冲突→终局" | 分卷目标数量与原书一致（卷数由用户定） |
| 节奏结构 | `保留`（默认）/ 微调 / 重写 | 保留高潮频率/危机频率/章末钩子密度 | 每 N 章 1 小高潮、章末钩子密度 ≥ 70%（正文审计抽样） |
| 具体剧情事件 | **一律 0%** | 禁止复制 | forbiddenCopy 命中率 = 0（门禁） |
| 原人物/地图/势力/物品/术语 | **一律 0%** | 全部重建 | 词面检查 + 结构级审计（L1） |
| 微创新强度 | `轻`（默认）/ 中 / 强 | 轻=仅换皮+1 个新限制 | 偏离矩阵风险等级 ≤ low（默认） |

> 说明：**不提供百分比**——百分比无法被机器验证。用"级别→提示词约束→验证规则"三元组取代。

### 3.2 规模参数（联动成本，见第七节）

总章数（10-100/自定义）、卷数（≥1）、每卷章数、单章目标字数、每章场景数、是否预生成全卷大纲、是否只生成第一卷/前 10 章。

### 3.3 线索选择（主次权重）

用户可多选 10 条线（升级/复仇/感情/师徒/家族/组织竞争/宝物/世界真相/团队/商业权谋生存），必须给出**主次**：主线索 ≤2 条驱动全书，次线索 ≤4 条分卷推进，其余丢弃。主次直接写入 Bible `arcPlan` 与 `chapterPlan`。

### 3.4 模型与 Skill

沿用主编辑器现有控件（模型/Skill/思考/历史会话），新增：**预算上限**（见七）、**单阶段模型切换**（简报/框架/正文/审计可不同模型）、**章节级模型**。

## 五、依赖顺序（DAG，明确先决）

```
P0 统一主创书入口（迁移矩阵落地）
  └→ P1 参数 + 创作圣经字段补全（3.1-3.4 + 第四节）
       └→ P2 原创内容替换层（先生成人物/地图/势力/物品/术语，再生成分卷章节）
            └→ P3 正文生成服务端闭环（Bible→合同→场景→正文→审计→提交快照→CAS）
                 └→ P4 结构级原创审计（依赖 P3 产出的事件/图谱数据）
                      └→ P5 成本 + 真实评测 + 黄金集
```

**关键依赖说明**
- **P4 依赖 P3**：事件链/地图/势力结构比对需要"新书的事件级数据"——只有 P3 正文闭环跑通、章节提交产出事件/状态后才有比对对象。**顺序不可颠倒**。
- **P2 在 P3 前**：人物/地图/势力先定稿进 Bible，正文生成才不会"边写边临时改名"（修复《烬潮铸命》人物名不一致问题）。
- **P5 的评测需要 P3 的正文产物**：黄金集样本 = 真实写章 + 审计 + 状态快照。

## 六、正文生成服务端闭环（含提交强制检查）

### 6.1 闭环（主链路 `completion-editor.js` 接入）

```
读 Bible(GET /bible) + 上一章快照(GET /state?chapterNo=n-1)
→ 生成章节合同(POST /chapter-contract)
→ 场景合同（本地按 contract.goal 切分场景）
→ 逐场景生成正文（模型）
→ 服务端连续性审计(POST /audit，含 forbiddenCopy 词面检查)
→ 审计失败 → 保留草稿 + 定向修订（不提交）
→ 审计通过 → POST /commit（写人物/关系/时间线/伏笔状态 + creation_state_snapshots + CAS）
```

### 6.2 服务端提交强制检查（`/commit` 必须校验）

| 检查 | 规则 |
|---|---|
| `auditStatus` | 必须为 `passed`，否则 422 |
| 正文非空 | `content` 长度 > 0，否则 422 |
| 正文长度 | ≥ 单章目标字数下限（如 1000 字），否则 422 |
| `contentHash` | 与实际正文 hash 一致，否则 409/422 |
| 章节号不倒退 | `chapterNo > book.current_chapter_no`，否则 422 |
| Bible 版本不过期 | `bibleVersion == book 当前版本`，否则 409 |
| 状态版本冲突 | CAS `WHERE current_state_version = base` 失败 → `409 needs_rebase` |

> 注：`/commit` 的 CAS 与部分检查已实现（`handleCreationBookCommit`）；需补 `auditStatus/contentHash/bibleVersion/章节号` 校验。

## 七、成本模型（用 `model_usage` 落地）

### 7.1 单位成本公式

```
每章正文成本 = 合同(1) + 场景数(1-3) + 审计(1) + 重写(0-1 × 失败率)
向导成本   = 简报(1) + 框架(1) + P2 世界/地图/关系(2-3) + 偏离矩阵(1) + 用户单项重生成(每项 1)
```

### 7.2 实测锚点（本仓库真实运行）

| 锚点 | 值 |
|---|---|
| 整书拆解（1647 章） | 436 批模型调用，约 7 小时 |
| 创书向导（20 章） | 简报 + 框架 = 2 次调用 |
| 模型 | gpt-5.6-luna（当前默认） |
| 记账 | `model_usage` 表已建、requestId 幂等；**`credit_cost` 目前记 0，需从 `molan_usage` 的 cost 字段补** |

### 7.3 预算规则

- 每任务创建时写入 `estimated_credits`（= 章数 × 每章估算 + 向导估算 + 预留 20% 重写）
- 每次调用后累加 `model_usage.credit_cost` → 超过 `estimated_credits` → **暂停**（任务/向导置 `paused_budget`）
- 恢复：用户追加预算或调低参数（减章数/场景数）
- 前端每步显示"预计消耗 / 已消耗 / 剩余"（读 `/api/usage` + 任务 meta）

### 7.4 需要做的代码改动

1. `recordModelUsage` 补 `credit_cost` 来源（当前为 0）
2. `handleCreationBooksCreate`/`handleCreationBookCommit` 写 `budgetState`
3. 向导每步调 `POST /api/usage` 或在响应里返回 `usage` 累积

## 九、原创审计分层（确定性优先）

| 层 | 检测项 | 数据源 | 依赖 |
|---|---|---|---|
| L0 词面（已实现） | forbiddenCopy 命中 | 正文 | 无 |
| L1 结构级（P4） | 人物功能组合 / 事件链顺序 / 金手指功能等价 / 地图拓扑 / 势力关系结构 / 升级阶段对应 / 独特桥段 / 章节标题节点 / 角色关系变化路径 | **新书事件+图谱**（P3 产出） vs 原书 claims/edges | P3 |
| L2 模型复核 | 仅对 L1 输出 `riskLevel≥medium` 的样本调用模型 | 低置信样本 | P4 |

**L1 落地（给算法骨架）**
1. 新书每章提交时抽取事件（复用拆书 `extractBatchFacts` 的 schema）→ 得新书 events/entities
2. 事件链相似度：把原书事件序列与新书事件序列按"功能归一化"（动作类型 + 参与角色功能 + 结果类型）编码为向量，算 **最长公共子序列/编辑距离**，超阈值报警
3. 人物功能组合：角色"功能标签集"（主角/导师/竞争者/反派/队友 + 关键行为）做集合 Jaccard 相似度
4. 地图/势力：拆书 entities 的层级（省/城/宗/族）与 Bible map 的层级做树结构相似度

**输出 schema**（审计结果）
```json
{ "riskLevel": "low|medium|high", "diverged": true, "reasons": [],
  "matchedStructures": [], "requiredChanges": [] }
```
