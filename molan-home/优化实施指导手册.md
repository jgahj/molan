### 1.3 当前已知问题清单（本手册要修的就是这些）

1. **评测体系是假的**：scripts/eval/report.json 显示 `model: "n/a"`、全部样本 `from: "fixture"`——从未测过真实模型输出
2. **skill 叠加冲突**：用户手选 skill 时默认 skill 仍被注入（server.js 4658 行只检查默认 skill 自己的 block）
3. **callMolanChat 三处缺陷**：无默认超时；非流式失败时把原始响应当正文返回（9742 行 `if (!output) output = raw`）；skill 通道写死拆书专用（9692-9699 行）
4. **无进程级异常兜底**：全文件没有 uncaughtException/unhandledRejection 处理
5. **素材库 strong 模式未发布**：lib/character-material/quality-report.json 的 `published: 0`；且匿名化在破坏文本（普通词如"温暖/平静/大哥"被替换成 `[人物]` 占位符）
6. **创书质量门禁不过线**：contract_pass_rate=0.5、originality_block_rate=0.5（fixture 数据，需真评测确认后修复）

## 第二部分：硬性约束（违反任何一条都会造成生产事故）

1. **POST handler 必须用 `readBody(req)` 解析请求体**。本项目没有 body-parsing 中间件，直接访问 `req.body` 是 undefined。
2. **所有 SQL 必须参数化**（`db.prepare('... WHERE id=?').run(x)`），禁止字符串拼接。
3. **node:sqlite 不支持 `db.transaction()`**，事务只能手动 `BEGIN IMMEDIATE` / `COMMIT` / `ROLLBACK`。
4. **前端渲染用户内容必须走 `esc()` 或 `sanitizeHtml()`**（completion-editor.js 209/310 行已有）。
5. **忽略客户端传的 `source`/`apiKey` 字段**，模型 key 只从服务端配置取（server.js 1382 行已有此逻辑，不得破坏）。
6. **不修改以下目录**：`books/`、`raws/`、`raws2/`、`extracted/`、`deploy_tmp/`、`tmp-booktest/`、`ai-novel-landing/`、`maliang*`（这些与本项目无关或是数据资产）。
7. **每个新增函数必须有函数级注释**（中文，说明用途、参数、返回值）。
8. **改动前先 Read 目标代码段**，确认行号未漂移；搜索用函数名不用行号。
9. **每完成一个任务立即跑 `node --test`**，出现失败先修复再继续。
10. **Git 提交**：每个阶段结束提交一次，消息格式 `阶段N: 概要（测试X项全过）`。未经用户明确要求不 push。

#### 任务 1.1：runner.mjs 增加 --live 模式

**目标**：评测能调用真实模型，而不是只跑 fixture。

**改法**：
1. Read `scripts/eval/runner.mjs` 全文，理解现有 fixture 流程
2. 增加命令行参数解析：`--live`（真实调用）、`--base-url`（默认 `http://127.0.0.1:3000`，从环境变量 `MOLAN_PORT` 读端口）、`--email`/`--password`（测试账号，可用环境变量）
3. live 模式流程：
   - 先请求 `/api/auth/login`（看 server.js 中登录路由的实际路径与请求格式，用 Read/Grep 确认）拿 token
   - 对每个样本，按其 task 类型构造 `/api/chat` 请求（参照 test/creation-flow.test.js 里已有的调用方式），拿流式响应
   - 解析方式参照 server.js 9715-9743 行 callMolanChat 的流式解析（`data:` 行解析 + `molan_usage` 提取）
   - 判分逻辑复用现有 metrics.mjs 的计算函数
4. report.json 输出强制校验：`model` 和 `promptVersion` 为空时加 `"invalid": true` 字段
5. live 模式必须记录每次调用的 `usage.requestId` 到 report.json 的顶层 `requestIds` 数组

**验证**：
```

node scripts/eval/runner.mjs         # fixture 模式，行为与之前一致
node scripts/eval/runner.mjs --live  # 需 server 运行中；report.json 出现真实 model 名
```

#### 任务 1.2：金标准样本集（20 个）

**目标**：构造有判分依据的评测样本，存 `scripts/eval/fixtures/golden.jsonl`。

**构造规则**（每行一个 JSON 对象）：
- `contract` 类 6 个：输入 = 一段章节大纲描述；期望 = 合同必填字段（goal/protagonistAction/opposition/informationChange/irreversibleResult）非空且具体（含至少一个名词性实体）
- `originality` 类 6 个：**3 个负样本**（把一段原文换人名后作为"生成结果"，期望 blocked=true）+ **3 个正样本**（借鉴句式但换了情节的段落，期望 blocked=false）。负样本源文本可从 `../人物描写素材库_真实抓取版.md` 取
- `entity_state` 类 4 个：输入 = 两章文本；期望 = 指定实体在第 2 章的状态变化（人工标注）
- `claim` 类 4 个：输入 = 章节文本；期望 = 人工标注的客观事实列表，每个事实标注是否有原文证据

**验证**：新增 `test/golden-fixtures.test.js`，校验 golden.jsonl 每行符合 schema（字段齐全、originality 负正样本各 3、总 20 条）。`node --test` 全过。

#### 任务 1.3：报告门禁
