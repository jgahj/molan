# 双书精读试点

## 当前实施范围

入口 `/pages/xuanhuan-reading.html`，网站创书入口显示“双书精读”；旧盲测入口保留为“旧盲测记录”。使用现有网站账户，不另存密码或会话令牌。

仅顺序阅读 `资源库/小说原本/玄幻` 中的《元始法则 - 飞天鱼.txt》《剑烛大荒 - 爱潜水的乌贼.txt》各前三章。本地文件按完整字节计算 SHA256，只读访问。当前两份文件可严格解码为 UTF-8。段落保留原文位置，偏移单位为解码后的 UTF-16 code unit，不是字节。序章计入阅读；未知前言停止供人工核查，不静默删除。

章前收藏宣传和明确标记的章末 PS、作者注释、已核实的《元始法则》第三章宣传附言不作为故事正文。附言保留内容与位置供导出核查，原文件不修改。解析器不是通用广告分类器；对其他版本需重新核查边界。

## 精读而非统计

每条路线顺序执行：完整连续段落阅读 → 章节综合 → 单独模型证据复核；每本三章完成后，用三章全文与经复核笔记进行跨章复盘。前一章的复核笔记传入下一章，另一书的内容不传入。每章正文不抽样、不切掉尾部；超出预算停止，不以摘要代替未读正文。

两本各自顺序、最多并行两次调用。某条路线失败不会把未复核内容传给后续章节，另一条独立路线可完成后再共同报告中断。

笔记分别记录事实、推断和待后文确认的问题，以及具体证据、推理、其他解释、迁移方法、适用条件。引用必须逐字命中指定段落；每条判断至少一条不少于8字的支撑引文，短对白可作为补充，不把引文长短当内容质量。复核必须覆盖所有判断编号，不确定结论不得保留为事实。跨章复盘至少两条判断有来自不同章的原文证据。

段落覆盖数组只是完整输入与模型回执核查，不保证实际理解；引用准确不保证因果推理正确。复核是模型复核，不是人工审定。没有词频、平均句长、风格统计分或“超过40分才通过”等文学验收规则。也没有强制情绪动作、总禁解释或每章反转模板。

模型抄对原句却标错段落时，仅在同章存在唯一逐字匹配且引文至少8字的条件下纠正段落编号，保留 reportedParagraphId 和纠正说明。跨章、歧义、改写引文都不自动修复；这是来源定位，不是修改模型判断。

若模型引用本身有误，恢复时可执行单独的模型引用修复调用，只提供有问题的判断与指定原段落。模型须明确原段落是否支持判断；不支持则停止，不能强行配引文。只替换对应引用，不重写判断或其他证据，保存旧引用、修复理由和来源尝试编号，再运行全阶段校验。该调用同样计入38次硬上限，不能被描述成又一次全文精读。

内部模型 HTTP 响应使用流式 UTF-8 解码，避免中文跨网络块被拆坏。SSE、非SSE和错误响应均有逐字节分块回归测试。笔记任何字段包含 Unicode 替换字符均停止，不靠猜字修补引用或推理。

## 接口与状态

认证接口前缀 `/api/xuanhuan-reading`；均按已验证账户隔离。资料保存在被 Git 忽略的 `data/xuanhuan-lab/reading.db`，不修改旧 `blind.db`。

- `GET /status`：指定原文件版本、阅读范围、当前任务。
- `POST /quote`：`{modelId}`，服务器核实账户可用模型、上下文和当前计费。
- `POST /jobs`：`{modelId,consent:true,maxCalls:38,maxCredits,chapterCount:3}`。不接受30章扩展。相同账户、模型、协议、原文件版本复用已有任务，避免重复启动。
- `GET /jobs`、`GET /jobs/:id`：历史记录、阶段进度、证据、原文位置、用量；原文变化时返回失效警告。
- `POST /jobs/:id/cancel`、`POST /jobs/:id/resume`：取消和显式恢复。恢复重新核验原文件、计费与剩余调用数。
- `GET /jobs/:id/export`：导出结构化笔记、证据、原文范围、已知用量和尝试记录，无需评分。

状态：queued → running → completed，或 interrupted / cancelled。完成后进入 awaiting-expansion-budget，不自动创书。服务重启将未完成任务标记为 interrupted。已保存有效阶段恢复复用，失败阶段不冒充成功。

失败原始响应与用量保留；校验器修正后，只有输入哈希相同、原始响应重新通过完整校验时才可恢复该阶段，不改写模型原文、不重发调用，并保留原失败记录与重新核验说明。解析规则更新若改变章节正文，相关章及后续章和该书复盘失效；旧尝试和费用不删除。

## 模型、计费与停止条件

试点要求网站实际可用、上下文至少100000 tokens 的模型；两本使用同一个模型。模型名称是网站配置别名，不据此断言上游真实版本或能力。调用使用独立分析提示，不注入旧 writing 阶段规则。

当前六章各一个连续输入段，正常需20次调用：6次阅读、6次综合、6次复核、2次跨章复盘。38次硬上限涵盖所有失败尝试。每次输出最多6500 tokens；输入按字符保守估算并额外预留，输入加输出保护值不得超过90000。整轮积分预估向现有计费接口明确传入3420000 tokens，而非使用接口默认的2048 tokens。

未知计费、模型不适用、余额/鉴权失败、源文件变化、输入预算超限、无效笔记或调用次数耗尽都会停止；不自动无穷重试。恢复会重新确认计费，不允许超过原确认积分预算。已知扣费超过预算也停止后续调用。token 保护是估算，不是精确 tokenizer；实际账单为准。

管理员账户可能预估与实际积分扣费为0，不能据此称上游调用免费。记录上游返回的 tokens 和 creditCost；缺失记录不当作零。在途未保存请求可能在恢复后重发并再次计费，不能保证跨进程恰好一次。

```text

```

真实任务完成后只读审计：

```text
node --experimental-sqlite scripts/audit-xuanhuan-reading.cjs <任务ID>
```

审计核验原文件指纹、段落覆盖、证据位置、复核覆盖、跨章证据、调用上限和用量。可以读取前30章的字符体量用于预算外推，但不把字符盘点称为精读。27章后续用量估计不包括30章最终综合、重试与原创试写，不能当成固定报价。

下一阶段仍等待用户确认试读成果与扩展预算：各顺序精读至30章、建立两套经复盘的方法库、两条路线各自创作一本原创小说并交付连续3章。本试点不会把未经用户认可的笔记自动注入当前编辑器；没有微调、没有偏好训练、没有新的盲测评分要求。
