# 墨阑全量功能缺陷修复 Spec

## 目标

修复最近审查中已确认、会影响用户操作结果或数据正确性的功能缺陷，保持现有 UI 视觉风格与后端接口兼容。范围覆盖主工作台、编辑器、导入/拆书、小说库、Skill、账户状态和管理后台。

## 修复范围

- 编辑器：大纲标签切换、弹窗生命周期、保存竞态、多卷定位、生成结果防串目标、空卷初始化、AI 历史上限、移动端抽屉互斥、错误结果防插入、字数参数、登录门禁。
- 导入/拆书：任务轮询隔离、停止状态、失败文案、结果完整性校验、重试模型固定、批量积分展示、同名资源唯一性、完整结果展示与入口门禁。
- 小说库/账户：本地草稿与云端 ID 边界、删除后实时同步、重命名并发保护、账户切换旧请求隔离、未开放登录入口的可用反馈。
- Skill/平台：搜索与排序竞态、账户切换同步、知识库事件兼容、创书结果结构校验与字段落库。
- 管理后台：详情请求目标隔离、列表筛选竞态、模型/Skill 加载错误态、Skill 未保存提示、模型倍率与默认模型保存一致性。
- 主工作台/UI：全局弹窗路由清理、移动端面板互斥、知识库真实折叠、无功能按钮的明确反馈、API 基址兼容。

## 验收标准

1. 现有 `npm test` 全部通过，修改文件通过 `node --check`。
2. 所有 AI 结果在请求期间绑定作品/卷/章节/场景/会话目标，切换目标后不会写入新目标。
3. 保存、轮询、列表和详情请求不会被旧请求覆盖当前状态。
4. 拆书失败、停止、部分完成、完整完成状态可区分；结果为空或结构不完整时不能伪装成成功，也不能开放导出/创书入口。
5. 多卷作品、空数据作品、本地草稿和账户切换均有可用路径。
6. 功能缺失的入口要么接通现有真实逻辑，要么给出明确可用反馈，不保留无响应按钮。

## 约束

- 不修改数据库 schema、模型接口和部署配置。
- 不改动无关的安全、依赖、SHA 或数据库审计内容。
- 每轮修改前后清理临时验证代码，测试通过后提交 Git。

### 约束

- 不提交临时脚本、调试输出、测试 mock 或验证残留。

## 创书卡住修复 Spec（2026-08-20）

### 目标

保证创书请求在模型返回后能够完成结果校验、保存并进入编辑器；余额、用量和作品列表刷新失败或延迟时，不得阻塞创书主链路。

### 实现要求

- 创书按钮明确显示“生成中 → 校验结果 → 保存作品”阶段和已等待时间。
- 模型返回后先解析并校验创作包，再异步刷新余额与用量。
- 云端新作品使用本次创书固定 ID；保存请求超时后仍可进入编辑器并保留该 ID，后续保存可继续完成同步，不因重试制造重复作品。
- 云端保存设置有限等待时间；只有保存超时或网络中断时允许进入本地编辑状态，其他服务端校验错误必须明确提示并停止。
- 作品列表刷新只能后台执行，不能阻塞成功结果展示。

### 验收标准

1. 模型返回后，即使 `/api/auth/me`、`/api/usage` 或 `/api/novels` 列表请求不响应，创书也能完成校验并关闭弹窗进入编辑器。
2. 保存响应超时后，按钮会恢复，用户能进入编辑器并看到明确的云端同步提示；再次保存使用同一作品 ID。
3. 创书正常成功时，作品保存、编辑器打开和实际积分提示均保持可用。
4. `node --check completion-import.js`、`npm test` 和 `git diff --check` 通过。

## 创书确认按钮恢复 Spec（2026-08-20）

### 目标

创书请求结束或重新打开创书弹窗后，确认按钮必须恢复可点击，不能继承上一次请求留下的禁用状态。

### 实现要求

- 每次打开操作弹窗都重置确认按钮的 `disabled` 状态和旧的等待文案。
- 创书云端保存成功或超时进入编辑器状态后，重新绑定当前作品会话，再执行结束清理。
- 请求结束清理只影响当前弹窗按钮，不因旧作品会话快照失效而跳过恢复。

### 验收标准

1. 创书成功后重新打开创书弹窗，确认按钮可点击。
2. 创书保存超时、校验失败或账户切换后，按钮不会永久禁用。
3. `node --check index.html`（通过内联脚本提取检查）、`node --check completion-import.js` 和 `npm test` 通过。

## 编辑器 AI 发送无响应修复 Spec（2026-08-20）

### 目标

修复新版 `completion-editor.js` 编辑器中 AI 助手发送入口点击无反应的问题，确保用户提交创作任务后始终能看到请求状态或明确的失败原因。

### 实现要求

- 发送按钮只绑定到当前编辑器实例，重新渲染编辑器后仍保持可用。
- 请求开始前校验作品、当前章节、AI 请求接口和输入内容；任一条件不满足时给出明确提示，不静默返回。
- 请求过程中按钮显示忙碌状态；成功、失败、取消和积分不足都恢复可点击状态。
- 上下文构建或模型请求异常必须写入对话区，不能留下永久“整理中/思考中”状态。
- 不改变现有编辑器 UI 风格、后端接口和数据结构。

### 验收标准

1. 编辑器加载后点击 AI 发送入口，能触发真实请求或显示明确错误提示。
2. 空输入、未打开作品、接口未加载、请求失败和请求完成均有可见反馈。
3. `node --check completion-editor.js`、`npm test` 和 `git diff --check` 通过。

## 新版编辑器思考强度与纠错库回接 Spec（2026-08-20）

### 目标

新版编辑器只更换了界面，必须恢复原编辑器已有的思考控制和默认写作纠错链路，不改变模型权限、计费和后端数据结构。

### 实现要求

- AI 右栏增加思考控制，随当前模型动态显示服务端声明的官方 `reasoning_efforts`；没有推理强度的模型沿用已有思考开关。
- 选择结果保存到当前作品设置，并在新版编辑器发起请求时传递给公共 AI 请求函数。
- `stage: writing` 的请求显式启用通用纠错库；纠错策略仍由服务端注入和审计，前端不复制提示词。
- 模型切换或重新渲染后，思考控制值与当前模型保持一致，不保留不受支持的档位。

### 验收标准

1. 新版编辑器右栏可看到并操作思考控制；GPT 类模型展示官方档位，DeepSeek 类模型展示开关。
2. AI 写作请求包含当前模型支持的 `reasoningEffort` 或 `thinking`，并显式启用 `correctionPolicy`。
3. `node --check completion-editor.js`、`node --check index.html`、`npm test` 和 `git diff --check` 通过。

## 编辑器思考控件可见性修复 Spec（2026-08-21）

### 目标

确保新版 `index.html#editor` 与旧版 `/pages/editor.html` 在模型能力接口异步、字段暂缺或浏览器缓存旧资源时，仍能显示并正确操作思考控制，不改变后端接口、计费和现有纠错链路。

### 实现要求

- 新版右侧 AI 助手显示独立的“思考强度”控件，GPT-5 使用官方档位，DeepSeek 使用开关。
- 当模型能力元数据暂时不可用时，按模型 ID 回退识别 GPT/DeepSeek 能力，不把已支持的控件隐藏或误显示为不可用。
- 旧版现有思考分段按钮增加明确标题，并与同一模型 ID 回退规则保持一致。
- 更新两套编辑器资源版本，避免继续使用旧缓存；写作请求继续显式启用纠错库。

### 验收标准

1. 两个入口均能在 AI 面板看到“思考强度”，GPT-5.6 显示 `关闭/极低/低/中/高/极高/最大`，DeepSeek 显示 `关闭/开启`。
2. 切换模型或刷新模型列表后，控件仍可见且值与当前模型能力一致。
3. `node --check completion-editor.js`、`node --check pages/editor.js`、`npm test` 和 `git diff --check` 通过。

## 新版编辑器 AI 超时无响应修复 Spec（2026-08-21）

### 目标

修复新版编辑器写作请求在模型思考、Skill 分析或纠错链路尚未返回首字节时被前端 20 秒总超时主动中断的问题，同时确保新版思考控件资源被重新加载。

### 实现要求

- 新版编辑器写作请求使用 120 秒前端等待上限，继续保留登录账户切换时立即中断。
- 不修改后端积分预扣、模型权限、纠错库和流式响应协议。
- 更新新版编辑器脚本版本号，避免已打开页面继续引用旧资源。
- 增加针对性回归断言，确认写作请求的超时配置和纠错参数仍然存在。

### 验收标准

1. 新版写作请求不会在 20 秒时提前显示“AI 请求超时”；正常模型响应可进入对话框。
2. 新版资源加载后能看到“思考强度”控件。
3. `node --check completion-editor.js`、`npm test` 和 `git diff --check` 通过。
